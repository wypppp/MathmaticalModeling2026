# 第三方模型：全程参与，但身份是"局外人"

> 原则：第三方的价值**不是多一份解法，而是它不知道我们的推理过程**。所以它在每个阶段都担任"局外人"角色：外审、测试员、审计员、评委。
> 第三方只读指定的输入文件，产出放在 `review/third_<阶段>_*.md`，由主工程方整合进裁决单。人不直接阅读第三方的长文档。

| 阶段 | 身份 | 输入（刻意限制） | 任务 | 产出 |
|---|---|---|---|---|
| G-1 选题 | 打分员 | 各题原文 | 按 `process/选题方法.md` 第 1–3 步打分 | 打分表 |
| G0/G1 | 盲点外审 | 原题 + spec | 按 AGENTS.md §3.1 的清单查盲点 | 盲点清单 |
| G2 | 路线发散 | 原题 + spec | 列方向；**专门找共识之外的洞察**（`差异化洞察.md`） | 路线与洞察 |
| **G3** | **独立测试员** | **只给 spec，不给代码** | 根据规格写测试用例：边界、退化、对抗算例，以及期望输出或可检查的性质 | 测试用例集。由主工程方运行，失败的用例进入裁决单 |
| **G4** | **语义审计员** | spec + 代码（不给我们的讨论记录） | 逐条核对代码与规格是否一致：有没有偷偷放松约束、单位或口径不对、边界没处理 | 不一致清单 |
| **G5** | **结果质疑者** | 结果表、图和结论（不给代码） | 找出不合理的数字、缺失的对照、证据撑不起的结论；提出必须补做的检验 | 质疑清单 |
| **G6** | **盲评委** | **只给论文 PDF** | ①只读摘要，复述论文的结论（复述有偏差，说明摘要没写清楚）；②按评分细则逐项挑缺陷；③指出最不可信的 3 处 | 评审意见 |

## 为什么后半程更需要第三方

- **G3 测试员**：写代码的人和写测试的人如果是同一个，会犯同样的错。只看规格写测试，等于对实现做一次独立检验。
- **G4 审计员**：GPT 作为审查方已经参与了讨论，带着同样的理解，可能和我们一起"看不见"问题。第三方没参与讨论，正好可以抓语义漂移。
- **G5 质疑者 / G6 盲评委**：评委就是局外人。只有局外人的视角，才能模拟评委第一次读到论文时的感受。

## 成本控制

- 每个阶段一次调用，输入文件固定。
- 测试员、审计员任务较难，用强档模型；摘要复述可以用轻量模型。
- 第三方的意见一律经主工程方核实后再进入裁决单：先验证，后采纳。
