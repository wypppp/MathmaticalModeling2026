## 最优性与穷尽性

旧报告所引 `review/gpt_G3/solve.py` 在可见 Git 历史中未找到。本次按旧报告重建其精确有理数 CP-SAT 模型，用独立检查器的附件读取逻辑读取附件 1、4、5。候选由原始需求生成，求解阶段不读参考指派。逐层得到以下界并固定。

1. 最大化 U9 交给 U6 的块数，最优为 **5**。
2. 最小化保留自有块的批次数，最优为 **32**。
3. 最小化代领代交量，最优为 **7075748498327716318318078686089447 / 651068375440131492428518413480000** 辆（约 10.867903841197032）。以分母最小公倍数整数化，按 10000 进位从最高位到最低位依次求最优并锁定。预筛用逐项向下取整的和作下界，用可行解的精确代领代交量作上界，因此保留所有精确最优解。运力同样先向下取整宽松筛选，再按分数逐批检查，发现超限就排除该载荷组合后重解。
4. 最小化时间窗不相交的（来源批次，执行批次）对数，最优为 **8**。同一对的多个块只计一次。

每层均取得 `OPTIMAL`。固定这四个目标后，对每次得到的完整指派加入一条割，限制 90 个块中至多 89 个保留该去向。去向包含执行批次、实际装卸端点、R4 领回批次及反转标记，同一路径的等价规则标签合计。独立发现顺序为 0、2、1，第三条割之后为 `INFEASIBLE`。各层状态、A 的整数位与末次状态见 `solver_log.json`。

分配层放宽 C4 提供最优界。随后对每个解的每一批，用附件 1 直达距离从驻地出发、返回驻地，构造全程不留置的路线。每次停靠均有实际作业，至多到访同仓两次，按先卸后装记录各块操作。搜索检查货流先取后送、S12 首装与末卸、R5 取代交货的先后，以及每段精确在途载重不超过本批 T。R4 的第二程另计入领回批次载荷。三组共 96 条路线全部满足 C4，最长见证为 1961 km，故三个解在原问题中均可行，放宽模型的穷尽性也排除了其他四级并列指派。`routes.csv` 给出每批路线、里程、原批号、运力和逐站装卸的块号及精确在途载重。这里验证的是问题 2 单批里程可行性。

## 对照与复现

`verify.py` 先用独立解计算指标和构造路线，再读取固定提交的参考 CSV。按块号核对每组 90 行，核对原批、货主、仓库、方向、存放仓、内部互转标记、自有或转移、执行批次与单位、规则、R3/R4 附属去向和两种车型下的等效量。三份 `assign_tie*.csv` 各 90/90 一致；`ties.csv` 的指标与选择标记一致，导出的浮点数按相对容差 1e-12 对照。旧 GPT 逐块台账与指派 0 的执行批、规则、货流端点和领回批次完全一致；基准的 `assign_main.csv` 与指派 2 的 90 行一致。第五级使用 spec §17 的共用标尺选优；本项核对了主解身份，未重新求解问题 3。

在已获取基准提交的仓库中运行；目标分支的附件 1、4、5 与基准相同。环境使用 Python 3.12、openpyxl、OR-Tools 9.15.6755，单线程、随机种子 0。
