# 一、代码比 spec 更宽或更窄

## 1. S9 同时到达排序：引擎用「(出发日, 批次号)」，spec 要求「按批次号」 —— f_engine.py:233（更宽）

- **spec 条目**：S9「先到先服务……同时到达按批次号」。
- **位置**：`f_engine.py:233` `heapq.heappush(heap, (arr, p.start_day, p.bid))`。注释自称「同时到达按输出批次号……与检查器一致」，实际键里塞了 `start_day`；检查器 `f_check.py:351` 的 `sort(key=(arrive, _b))` 才是 spec 口径。
- **问题**：事件堆的弹出顺序就是仓库的服务顺序。两批同时到达同一仓库、且「出发日早」与「批次号小」不是同一批时，引擎先服务出发日早、批次号大的批。日容量紧张时这决定谁 spill 到次日；检查器再按 spec 口径重排，会对求解器自己产出的结果表报「时刻/离开时刻」违例，求解侧也按错误排队优化。
- **最小算例（已运行验证）**：批 2（U1，出发日 40，驻地→WA，WA 作业 12 台次）与批 5（U2，出发日 39，驻地→WX→WA，WA 作业 12 台次），两段路 62.5 / 500 km，两批均于第 40 天 9:00 同时到达 WA；10:00 后当天只剩 15 台次额度。引擎服务顺序批 5→批 2：批 2 做 3 台次后 spill 到第 41 天（实测批 2 作业至次日 10:36）；spec/检查器顺序批 2→批 5：批 5 spill。两口径结果完全对调。

## 2. S12/S15：在队属仓卸完接领货后禁止再到任何外部站（含无作业汇合站） —— f_routes.py:179-181（比 spec 窄）

- **spec 条目**：S12（经 U1 续裁决）禁止的是这之后在外部仓库**作业**；S15「除汇合站和终点驻地外，不出现不作业的站」——无作业的汇合站本来就允许出现在路线任何位置。
- **位置**：`f_routes.py:179-181`：`is_ext = n.startswith("W") and n not in own_set; if back and is_ext: continue`。`back` 一旦置位，后续所有外部候选站（含纯 rejoin）都被剪。检查器同错：`f_check.py:224-225` 把「在队属仓卸接领货后又出现在外部站（哪怕 `n in left` 的纯汇合）」报 S12。
- **问题**：存在 spec 可行、且 P3 目标更优的路线被剪掉（P3 目标不含总里程，「L̄ 换 D」的路线会被选中，剪枝直接改变最优解）；同一条 spec 合法路线写进结果表会被检查器误报。
- **最小算例（已运行验证）**：U1，H(U1)={WH1, WH2}；货组 k1: WB→WH1（接领，s=6）、k2: WA→WH2（接领，s=6），T=12。spec 合法路线：驻地→WA（装 k2 并依 S11 全部留置）→WB（装 k1）→WH1（卸 k1）→WA（纯汇合，无作业）→WH2（卸 k2）→驻地。k2 全程只计 WA→WH2 一段载货距离，L̄ 严格小于「汇合发生在 WH1 之前」的变体（实测枚举 8 条路线，该路线不存在，只有 rejoin 提前的等价劣路线）。

## 3. R3 守恒放行条件写宽了 —— f_check.py:513-516（检查器比 spec 宽）

- **spec 条目**：R3「存在 h_x∈H(x) 使 d(货主驻地, h_x) ≤ 150」，≤150 的是**替代存放仓**。
- **位置**：`min(D[(key[0], n1)], D[(key[0], n2)]) <= 150`——差异的两个节点里只要有一个 ≤150 就放行。
- **问题**：货被卸到距货主 >150 km 的另一队属仓时，只要**原存放仓** ≤150 km 就判「守恒 OK」，漏报。
- **最小算例**：U4 驻地距 WR 10 km、距 WS 300 km；某批替 U4 代领的货应卸 WR 却卸在 WS。差异节点 {WR:−q, WS:+q}，`min(10, 300)=10 ≤ 150` → 检查器放行；按 spec 替代仓 WS 距货主 300 km，非 R3，应报。

## 4. W_β 口径：代领代交段一律不进 targets —— f_check.py:298-302（检查器比 spec 窄，C1 与批次-仓库对漏报）

- **spec 条目**：§4.1 `W_β = {w_k : k∈K_β} ∖ H(x) ∖ {R5/R7 专程取货仓}`，K_β 含全部被执行块；C1 `|W_β|≤4`、附表 4「批次-仓库对」。
- **位置**：`f_check.py:299-302` 把 `flag≠0`（代领/代交）的外部段全放入 `special`，`targets` 只收 `flag==0`。C1 用 `len(_targets)`（:434），批次-仓库对用 `len(_targets)`（:462）。
- **问题**：正常指派下被转块的 w_k 已被自有段覆盖，口径碰巧相等；但检查器**不重推** R 情形前提（w_k∈W^own 等），一旦指派层出错，|W_β| 少计，C1 和批次-仓库对都漏报。
- **最小算例**：某批自有块只到 WA，另替人代领到 WB（WB 不在本批自有目标中，不满足任何 R 前提）。spec |W_β|=2 违反 C1；检查器 `targets={WA}`，不报。

## 5. S15「每站至多 2 次」检查器无对应检查（检查器比 spec 宽）

- **spec 条目**：S15（H10）「同一作业站可以重复到访（每站至多 2 次）」。
- **位置**：求解侧 `f_routes.py:20, 150, 165`（MAX_VISIT=2）有；`f_check.py` 全文无到访次数检查。
- **最小算例**：任意批对同一仓库装→卸→再装（三次到站）的结果表通过检查。求解器不会产出，但检查器对任何非求解器产出的表不拦截。

# 二、检查器没有独立重推、与求解代码同写法的判定

这类是本项目最危险的位置——求解侧写法一错，检查器跟着错。

1. **travel（S5/S6）整体移植**：`f_check.py:140-154` 与 `f_engine.py:92-113` 逐行同构：≤500+EPS 短段、16:00 含、到达钳到 `min(DAY_H,·)`、>500 次日 8:00 + `ceil(dist/500)` 分段。任何一处算术错，检查器同步错。另潜伏一处不一致：引擎容忍度 1e-9、检查器 1e-6（`f_engine.py:107` vs `f_check.py:147`，及长段 `h>EPS` vs `h>1e-6`），附件整数公里下不触发，但属同源移植时的手滑。
2. **装卸模型（S7/G7/G15）**：`c=⌈s⁺⌉+⌈s⁻⌉`、2.5 台/时、16:00 滚次日、当日做一部分次日续——`f_check.py:315-329` 与 `f_engine.py:130-155` 同一套循环。
3. **仓库队列与日容量（S8/S9）**：先到先服务、`free_at`/`free` 串行、单位名额「当天确有作业才占」、3 单位 / 20 台次、容量不足 spill 次日、自用仓只排队免容量——`f_check.py:350-373` 与 `f_engine.py:123-158` 同一控制流（含同一处语义选择：单位名额满时整日跳过，`f_engine.py:143-145` 与 `f_check.py:362-364`）。
4. **S10 等待天数计数公式**：排队车队 `f_check.py:374` ↔ `f_p3.py:121`（`start−arrive−1+(8:00 整到 +1)`）；留置 `f_check.py:411` ↔ `f_routes.py:213-214`（`resume−leave_end−1+(≥16:00 +1)`）。「8:00 到齐等一整天算 1 天」「resume 当天 ≥16:00 再加 1」这两个解释两边逐字相同，并非各自从「整天既不作业也不行驶」独立推出；且两支「+1」分支在双方实现里都是不可达代码（serve 的 16:00 翻滚保证 start<16:00，无作业汇合的离开只会是到达时刻或次日 8:00），说明这段公式是从一个已废弃的口径抄来后没人重验。
5. **S12 的 ext/back 状态机**：`f_check.py:213-214, 222-225, 282-287` ↔ `f_routes.py:141, 177-185`（`first_ext`/`ext`、`back_at`/`back` 同定义、同判定时机），包括一-2 那处共同的过紧解释——检查器永远不可能就这一点纠正求解器。
6. **S11 留置=当前全部已装（X2 字面）**：`f_check.py:303-311` ↔ `f_routes.py:190-194`。且检查器的「留置」判定依赖结果表 `follow` 列的「是/否」——该列由求解侧在生成路线时一并写出；若路线与标注脱节，检查器没有独立信息源（movT 只会在 follow 标「否」时扣减）。
7. **R4 的两个判定时点与端点定义**：`f_check.py:467-478, 488-493` ↔ `f_p3.py:131-137`。都是「β 卸完=排队修正后的作业结束（`endq`/`lg.end`）」「β′=装车站到达时刻」「整批先后=出发日 vs 回驻地日，回驻地日=末站**到达**日（`f_engine.py:218` ↔ `f_check.py:415, 458`）」。更关键的是检查器对 R4 的**识别**依赖求解输出备注里的「暂存」「领回」字样（`f_check.py:269-270, 291-292`），求解侧漏标/错标时对应 R4 检查静默跳过。
8. **send/recv 分类与 T=⌈max⌉**：`f_check.py:293-297, 423` 的 `is_send=(自仓装∧外仓卸∧flag=0)∨flag=−1` 与 `f_routes.py:83-98` 的 `_is_send` 逐字等价（含「代交恒为送交侧」这一可争议归类，两边一致）。
9. **L̄/车公里「货在车上才计程、留置期间 0」**：`f_check.py:238-239, 441-443`（onboard 行 `g[4]+=d`）↔ `f_engine.py:231-232, 216-219`（`L[g]+=d_km`）。同一实现，算术错不可见。
10. **τ、end_day、V、δ、S4 的活动日窗口**：`end_day=末站到达日`、`τ=end−start+1`、`act[日]` 含首尾、`V` 按（原批次, 执行批次）对——`f_check.py:415, 432-433, 444-457` ↔ `f_engine.py:218-220` ↔ `f_p3.py:115-116, 140-141`，同一组定义。

# 三、边界情况

## 1. 同一时刻到达的先后

见一-1。补充：该 bug 的隐蔽处在于 `f_engine.py:233` 的注释白纸黑字写着「与检查器一致」，任何人对照注释而非对照键都会放过；键应改为 `(arr, bid)`。

## 6. 同一仓库一批到访两次

求解侧正确（每次到访独立 `serve`、`free_at` 串联、两次都计日容量与单位名额、`visits` 上限 2）；问题只剩检查器无 ≤2 次限制（见一-5）。

其余四条边界（恰好 16:00 到达或完工、跨日装卸、恰好 500 km、留置后汇合站当天排队）逐个推演并对了双方实现：到达钳 16:00、16:00 到/完工一律次日 8:00 续、500 km 属短段（含 16:00 整到）、跨日续做两日都占名额、汇合后排队计入 resume（W3，求解用 `lg.start`、检查用 `_first`），两边一致且无死分支外行为，按「只列问题」的要求不展开。
